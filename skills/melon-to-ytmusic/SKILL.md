# 멜론 → 유튜브 뮤직

멜론 플레이리스트를 유튜브 뮤직으로 옮기는 CLI(`mtym`)를 운전한다.

## 시작하기 전에

**루트 찾기.** 이 SKILL.md 기준으로 두 단계 위가 프로젝트 루트다
(`<루트>/skills/melon-to-ytmusic/SKILL.md`). `package.json`에 `"name": "melon-to-ytmusic"`이
있는지로 확인한다. 이하 `$ROOT`.

**결과물 위치.** 항상 `--data-dir`을 붙여 `$ROOT` 바깥에 저장한다. 플러그인으로 설치된
경우 `$ROOT`가 관리되는 캐시 위치라 업데이트 때 날아갈 수 있다.

```
--data-dir "$HOME/.melon-to-ytmusic/data"
```

**부트스트랩.** 첫 실행이면 의존성과 빌드가 없다. 한 번만 돌린다.

```bash
cd "$ROOT" && node scripts/bootstrap.js
```

이후 모든 명령은 이 형태다:

```bash
cd "$ROOT" && node dist/cli.js <명령> --data-dir "$HOME/.melon-to-ytmusic/data"
```

## 진행 순서

### 1. 로그인 확인

```bash
node dist/cli.js login
```

크롬 창이 뜬다. 둘 중 하나라도 로그아웃이면 **거기서 멈추고 사용자에게 직접 로그인을
요청한다.** 아이디나 비밀번호를 절대 묻지 않는다. 로그인은 사람이 브라우저에서 직접 하고,
프로그램은 그 세션에 붙기만 한다.

사용자가 로그인을 마쳤다고 하면 `login`을 다시 돌려 확인한다.

### 2. 옮길 플레이리스트 고르기

```bash
node dist/cli.js playlists
```

`<ID> <곡수> <이름>` 형태로 나온다. 왼쪽 숫자가 `--playlist`에 넣을 멜론 내부 ID다.
사용자가 이름으로 말하면 이 목록에서 ID를 찾아 쓴다. 이름이 모호하면 곡 수까지 보여주고
어느 것인지 확인받는다.

### 3. 곡 목록 수집

```bash
node dist/cli.js scrape --playlist <ID> --genres
```

무드별로 나눌 계획이 조금이라도 있으면 `--genres`를 붙인다. 나중에 다시 받으려면
곡 수만큼 시간이 더 든다. 900곡 기준 장르 수집에 5분쯤 걸린다.

### 4. 옮기기

```bash
node dist/cli.js migrate
```

900곡 기준 15~20분. 오래 걸리므로 백그라운드로 돌리고 진행 상황을 보고한다.
중간에 끊겨도 같은 명령을 다시 실행하면 이어서 간다.

끝나면 `<data-dir>/migration-report.txt`를 읽고 **반드시 사용자에게 요약해준다.**

- 매칭 실패한 곡
- 앨범/EP로 잘못 잡힌 곡
- 점수가 낮아 확인이 필요한 곡

곡 수가 안 맞으면 멜론 플레이리스트 자체에 중복이 있었을 수 있다.
`migration-state.json`에서 같은 videoId로 매칭된 곡을 찾아 설명한다.

### 5. 교정 (선택)

리포트에 앨범/EP 매칭이 있으면 제안한다.

```bash
node dist/cli.js repair            # 뭘 바꿀지 미리보기
node dist/cli.js repair --apply    # 실제 반영
```

**미리보기를 먼저 보여주고 사용자 확인을 받은 뒤에 `--apply`한다.** 확실한 것만 자동으로
고치고 애매한 건 목록만 나오므로, 그 목록은 사용자에게 그대로 전달한다.

### 6. 무드별로 나누기 (선택)

```bash
node dist/cli.js moods --dry-run   # 분류 결과만
node dist/cli.js moods             # 팝송/드라이브/잔잔 생성
```

`--dry-run`으로 곡 수 분포를 먼저 보여준다. `both/default`가 지나치게 많으면
(전체의 30% 이상) 그만큼 드라이브·잔잔이 겹친다는 뜻이니 사용자에게 알린다.

분류가 마음에 안 든다고 하면 `$ROOT/src/rules/moodRules.ts`를 고친다.
곡 규칙(`SONG_MOOD`)이 아티스트 규칙(`ARTIST_MOOD`)보다 우선한다. 고친 뒤:

```bash
npm run build && node dist/cli.js moods --recreate
```

`--recreate`는 기존 무드 플레이리스트를 지우고 다시 만든다.

## 지켜야 할 것

**계정 정보를 묻지 않는다.** 로그인이 필요하면 사용자가 브라우저에서 직접 하도록 안내한다.

**플레이리스트를 지우기 전에 확인받는다.** `moods --recreate`와 `repair --apply`는
유튜브 뮤직 계정에 실제 변경을 일으킨다.

**오래 걸리는 명령은 백그라운드로 돌린다.** `scrape --genres`, `migrate`, `moods`는
수 분에서 수십 분 걸린다. 진행 상황을 중간중간 보고한다.

**리포트를 요약해준다.** 사용자는 900곡을 일일이 확인하지 않는다. 매칭이 의심스러운 것만
추려서 보여주는 게 이 도구의 실질적인 가치다.

## 자주 막히는 것

**"Chrome 디버깅 포트가 열리지 않았습니다"** — 이미 실행 중인 크롬은 디버깅 포트를
나중에 열 수 없다. 크롬 창을 전부 닫고 다시 시도하도록 안내한다.

**"멜론에 로그인되어 있는지 확인해주세요"** — 세션이 만료됐다. `login`으로 상태를 확인하고
사용자에게 재로그인을 요청한다.

**곡이 엉뚱하게 매칭됨** — 정상 범위다. `repair`로 상당수 잡히고, 그래도 남는 건
표기 차이가 커서 자동으로 판단할 수 없는 경우다. 사용자에게 목록을 주고 직접 고르게 한다.
