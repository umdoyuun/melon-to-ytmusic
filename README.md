# melon-to-ytmusic

멜론에 몇 년치 쌓아둔 플레이리스트를 유튜브 뮤직으로 넘기려고 만든 CLI입니다.
900곡이 넘으니 손으로 옮기는 건 포기했고, 옮기고 나서는 무드별로 나눠 듣고 싶어서 그 기능까지 붙였습니다.

**비밀번호를 프로그램에 안 주셔도 됩니다.**
남이 만든 스크립트에 계정 비번을 적어넣는 게 영 내키지 않으시죠.
크롬 창을 하나 띄워주면 거기서 직접 로그인하시면 되고,프로그램은 그 세션에 붙어서 일합니다

유튜브 뮤직이 내부적으로 쓰는 API를 그대로 호출해서 사용합니다.
직접 사용해보니 1000곡 기준, 20분 정도 소요됩니다.

해당 프로그램은 멜론이랑 유튜브 뮤직의 비공개 API랑 DOM 구조에 기대고 있습니다. UI와 API 구조가 바뀌면 동작하지 않습니다.
2026년 8월 기준으로는 동작합니다. 유튜브 뮤직에 없는 곡은 당연히 못 옮기고요.
개인 계정 플레이리스트 옮기는 용도로만 만들었습니다.

## 준비물

Node 20 이상, 크롬, 멜론 계정, 구글 계정.

크롬은 설치만 되어 있으면 됩니다. `playwright-core`를 쓰기 때문에 브라우저를 따로 받지 않습니다.

```bash
npm install
npm run build
```

## 쓰는 순서

```bash
# 크롬이 뜹니다. 로그아웃 상태면 그 창에서 멜론이랑 유튜브 뮤직에 로그인하고 다시 실행하세요.
npm run mtym -- login

# 옮길 플레이리스트 번호 확인
npm run mtym -- playlists

# 곡 목록 수집. 나중에 무드별로 나눌 거면 --genres 를 같이 주세요.
npm run mtym -- scrape --playlist 558381546 --genres

# 유튜브 뮤직에서 찾아서 새 플레이리스트로 옮기기
npm run mtym -- migrate
```

여기까지가 기본이고, 아래 둘은 선택입니다.

```bash
# 앨범이나 EP로 잘못 잡힌 곡 교정. --apply 없이 돌리면 뭘 바꿀지만 보여줍니다.
npm run mtym -- repair
npm run mtym -- repair --apply

# 팝송 / 드라이브 / 잔잔 세 개로 나눠 담기
npm run mtym -- moods --dry-run
npm run mtym -- moods
```

빌드했으면 `node dist/cli.js <명령>`으로 써도 되고, `npm link` 하면 그냥 `mtym`으로 부를 수 있습니다.

중간에 끊겨도 괜찮습니다. 진행 상태를 계속 저장하기 때문에 같은 명령을 다시 실행하면 이어서 갑니다.

## 나오는 파일들

전부 `data/` 아래에 쌓입니다. 듣는 음악이랑 계정 식별자가 들어있어서 `.gitignore`에 넣어뒀습니다.

곡 목록은 `melon-playlist.json`과 사람이 보기 편한 `.tsv`로 같이 떨어지고,
장르는 `melon-genres.json`, 매칭 결과와 진행 상태는 `migration-state.json`에 들어갑니다.

눈여겨볼 건 **`migration-report.txt`** 입니다. 못 찾은 곡, 앨범으로 잘못 잡힌 곡, 점수가 낮아서
확인이 필요한 곡이 정리돼 있습니다. 무드 분류를 돌렸다면 `mood-assignments.tsv`에 곡마다
어느 플레이리스트로 갔는지와 그렇게 판단한 근거가 남습니다.

## 무드 분류 고치기

취향 문제라 정답이 없습니다. `src/rules/moodRules.ts` 한 파일만 고치면 됩니다.

```ts
export const ARTIST_MOOD = {
    'Dua Lipa': 'drive',        // 이 아티스트는 통째로 신나는 쪽
    'Billie Eilish': 'calm',
};

export const SONG_MOOD = {
    'Billie Eilish|bury a friend': 'drive',   // 아티스트 기본값을 덮어씀
};
```

곡 규칙이 아티스트 규칙보다 세고, 둘 다 없으면 멜론 장르로 판단합니다.
장르로도 안 갈리면 `both`로 두는데, 드라이브랑 잔잔 양쪽에 다 넣는다는 뜻입니다.
애매한 곡을 억지로 한쪽에 밀어넣는 것보다 이게 낫더군요.

고친 다음 `npm run mtym -- moods --recreate` 하면 다시 만듭니다.

## 곡 매칭에 대해

같은 곡인데도 멜론과 유튜브의 표기가 제각각이라, 제목이랑 아티스트 유사도만으로는 한참 모자랍니다.
실제로 깨져본 것들을 하나씩 반영했습니다.

먼저 **공식 음원을 우선**합니다. 뮤직비디오나 유저가 올린 영상 말고 `MUSIC_VIDEO_TYPE_ATV`요.

**앨범·EP·싱글 카드는 아예 배제**합니다. 이게 좀 성가신데, 이 카드들도 재생용 endpoint에
ATV 타입을 달고 옵니다. 그래서 타입 배제를 ATV 가산점보다 먼저 적용하지 않으면
앨범의 첫 트랙이 진짜 곡을 이겨버립니다. `Taylor Swift - Lover`처럼 앨범명과 곡명이 같을 때 터집니다.

**Instrumental이나 노래방 MR, 리믹스, 라이브**는 감점합니다. 멜론 쪽 제목에 그런 표기가 없는데
검색 결과에만 있으면 원곡을 찾는 상황이니까요. (`비비 - 철학보다 무서운건 비비의 총알`을
금영노래방 반주로 잡아온 적이 있습니다.)

마지막으로 **표기가 완전히 다른 경우**. `조또`와 `JOTTO`는 문자열로는 하나도 안 겹칩니다.
이럴 땐 유사도가 무의미하니까 유튜브 검색 순위를 훨씬 무겁게 봅니다. 로마자 표기나 번역까지
감안해서 정렬해주는 건 유튜브가 저보다 잘하니까요.

그래도 완벽하진 않습니다. 그래서 `repair`가 있는데, 확실한 것만 자동으로 고치고
애매한 건 목록만 보여줍니다. 어설프게 고치다가 멀쩡하던 곡까지 틀어놓는 게 더 나쁩니다.

## 설정

건드릴 일은 거의 없지만 필요하면 환경변수로 바꿉니다.

| 변수 | 기본값 |
|---|---|
| `MTYM_CHROME_PATH` | 자동 탐지 |
| `MTYM_CHROME_PROFILE` | `~/.melon-to-ytmusic/chrome-profile` |
| `MTYM_DEBUG_PORT` | `9222` |
| `MTYM_DATA_DIR` | `./data` |
| `MTYM_SEARCH_DELAY_MS` | `250` |
| `MTYM_ADD_BATCH` | `50` |
| `MTYM_LOW_SCORE` | `0.75` |

크롬 프로필을 평소 쓰는 것과 분리한 이유가 있습니다. 이미 실행 중인 크롬에는 디버깅 포트를
나중에 열 수 없기도 하고, 자동화가 개인 브라우저 세션을 건드리지 않게 하려는 것도 있습니다.
